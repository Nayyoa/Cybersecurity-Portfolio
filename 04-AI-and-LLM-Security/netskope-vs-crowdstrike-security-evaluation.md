
# Netskope vs. CrowdStrike AI Security Evaluation

## Enterprise GenAI & LLM Security Assessment

**Organization:** E2IP Technologies  
**Project Type:** Cybersecurity Engineering Internship  
**Focus:** AI Security | Proof of Concept | Security Policy Testing | Detection Analysis

---

## 1. Project Overview

This project involved the hands-on evaluation of two enterprise AI security solutions:

- Netskope One AI Security
- CrowdStrike AI Security

The objective was to assess their capabilities in protecting enterprise Generative AI and Large Language Model (LLM) usage.

The evaluation combined security policy configuration, controlled testing, detection analysis, and technical reporting.

Both solutions were evaluated through practical configuration and testing activities, including predefined and custom security policies.

The work formed part of a broader enterprise AI security initiative covering risk assessment, technical security controls, and AI governance.

---

## 2. Evaluation Objectives

The evaluation focused on the following objectives:

1. Assess AI security capabilities offered by both solutions.
2. Configure and test predefined security policies.
3. Create and evaluate custom security policies.
4. Examine sensitive information detection capabilities.
5. Evaluate security monitoring and visibility.
6. Identify false positives and false negatives.
7. Document technical findings and limitations.
8. Support the assessment of enterprise AI security requirements.

## 4. Evaluation Methodology

A structured testing approach was used to assess the solutions.

### Phase 1: Security Capabilities Review

Reviewed the security capabilities and configuration options available within each solution.

The objective was to understand how the platforms could address enterprise AI security requirements.

### Phase 2: Predefined Policy Testing

Evaluated existing security policies through controlled test scenarios.

The testing focused on verifying whether configured controls identified the targeted security conditions.

### Phase 3: Custom Policy Configuration

Created and configured custom security policies to evaluate detection capabilities beyond predefined configurations.

The objective was to assess policy customization and its relevance to enterprise security requirements.

### Phase 4: Detection Testing

Executed test scenarios and examined the resulting security events.

The analysis considered whether each security control produced the expected detection outcome.

### Phase 5: Results Analysis

Reviewed observed detections and investigated cases involving:

- Correct detections
- False positives
- False negatives
- Detection inconsistencies

### Phase 6: Technical Reporting

Documented test scenarios, observed results, limitations, and findings to support the evaluation.

## 8. Detection Accuracy and Testing Observations

Detection accuracy was an important component of the evaluation.

### True Positives

Cases in which a security policy correctly detected the targeted condition.

### False Positives

Cases in which a security policy generated a detection despite the tested content not meeting the intended detection condition.

### False Negatives

Cases in which a security policy failed to detect content that should have matched the targeted security condition.

### Detection Consistency

The assessment also examined differences in detection behavior across test scenarios.

For example, Netskope testing revealed differences in how certain French expressions referring to passwords were detected.

These observations highlighted the importance of evaluating security controls using realistic content variations rather than relying exclusively on predefined detection rules.
